# Public Safety Check Skill

このリポジトリは public で公開される。push・PR 作成の前に、個人を特定できる情報やプロジェクト固有の情報が含まれていないかを検査する。

## 入力

- PR ディスクリプションのファイルパス（あれば。なければ差分とコミットメッセージだけを検査する）

## 検査対象

1. `git fetch origin main` を実行してから、`origin/main` からの変更を対象にする
2. 変更ファイル: `git diff --name-only --diff-filter=d origin/main...HEAD`
3. 追加行: `git diff -U0 origin/main...HEAD`
4. コミットメッセージ: `git log origin/main..HEAD --format=%B`
5. PR ディスクリプションのファイル

未コミットの変更がある場合は、コミットしてから検査する（`git status --short` で確認する）。

## 1. 機械的な検査（grep）

変更ファイル・コミットメッセージ・PR ディスクリプションに対して以下を検索する。変更ファイルは行番号付き（`grep -nE`）で検索する。

| 検査項目 | パターン | 除外 |
|---------|---------|------|
| メールアドレス | `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` | `git@github.com`、`*@users.noreply.github.com`、`noreply@anthropic.com` |
| 個人の絶対パス | `/(Users\|home)/[A-Za-z0-9._-]+` | `/home/linuxbrew` |
| 実行環境のユーザー名 | `echo "$USER"` の値（`grep -niwF`） | なし |
| git のユーザー名 | `git config user.name` の値（`grep -niF`） | このリポジトリ自身の clone URL（`github.com/<name>/<このリポジトリ名>`） |
| フルネーム（macOS のみ） | `id -F` の値（`grep -niF`） | なし |
| 単語リスト | `~/.config/public-safety-check/denylist` の各行（`grep -niF -f <file>`） | なし |

- 単語リストは、プロジェクト名・会社名・サービス名などを1行1語で書くリポジトリ外のファイル。ファイルがなければこの検査はスキップし、結果にスキップしたことを書く
- 検出した値そのもの（ユーザー名・フルネーム・単語リストの中身）は、結果に書かない（ファイル名・行番号・検査項目だけを示す）

## 2. 内容の確認（Claude が読んで判断）

追加行・コミットメッセージ・PR ディスクリプションを読み、CLAUDE.md の「個人依存設定の禁止」に当たる記述がないか確認する：
- 他のリポジトリ・プロジェクトの名前や詳細
- 業務で扱う機能名・サービス名・環境構成・内部 API の仕様
- マシン固有・ユーザー固有の設定値（ホスト名、社内ドメイン、個人のディレクトリ構成など）
- 例文やルールが特定のプロジェクトを前提にした書き方になっていないか

## 出力フォーマット

```markdown
## Public Safety Check 結果

| 検査項目 | 結果 | 該当箇所 |
|---------|------|---------|
| メールアドレス | OK / NG | ファイル:行番号 |
| 個人の絶対パス | OK / NG | ファイル:行番号 |
| ユーザー名・フルネーム | OK / NG | ファイル:行番号 |
| 単語リスト | OK / NG / スキップ | ファイル:行番号 |
| 内容の確認 | OK / NG | ファイル:行番号 - 理由 |
```

## 重要ルール

- **NG が1つでもあれば push・PR 作成に進まない**: 該当箇所をユーザーに報告し、修正方針を確認する
- **コミット済みの NG はコミットから消す**: 修正コミットを足すだけでは履歴に残るため、コミットを作り直す方法をユーザーに確認する
- **検査結果に個人情報を書かない**: 検出した値は伏せ、場所だけを示す
- **見落としの可能性を伝える**: 内容の確認は文脈による判断のため、見落としがありうることを結果に添える
